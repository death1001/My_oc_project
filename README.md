# 角色资料查询器

基于 **Electron 33 + SQLite（better-sqlite3）** 的 Windows 本地角色资料管理工具。
面向小说 / 企划 / 跑团 / 同人创作者：集中管理角色档案、能力与武装、关系网络，
并为角色撰写可排序的小故事；另提供「独立故事库」用于跨角色的群像叙事。

完全离线运行，数据只存在本地 `data/characters.db` 与 `images/` 目录，不依赖任何网络服务。
这两个目录**不进 Git** —— 仓库里只有程序，你的角色设定与立绘永远留在本机。

---

## 快速开始

```bash
npm install      # 首次安装依赖
npm start        # 启动应用
npm run check    # 语法自检（8 个 JS 文件）
```

仅在 `better-sqlite3` 报 ABI 不匹配（`NODE_MODULE_VERSION`）时才需要 `npm run rebuild`；
本机无 Visual Studio C++ 工具链时，改用预编译包恢复，步骤见
[启动脚本与自检](docs/09-构建与运维/01-启动脚本与自检.md)。

## 功能概览

| 区块 | 能力 |
| --- | --- |
| 角色档案 | 20 列结构化字段：基本信息、能力、武器、战斗属性、四类关系、作品/初登场/稀有度/标签、头像与立绘 |
| 三种列表布局 | 列表 / 网格卡片墙 / 紧凑网格，设置内切换并记忆；卡片为 3:4 立绘封面，悬停有视差放大反馈 |
| 搜索与筛选 | 姓名+别名模糊搜索，阵营 / 种族 / 标签三维组合筛选 |
| 关系网络 | 手写 SVG 径向图，四类关系四色连线，点击节点按姓名跳转 |
| 双轨故事 | 角色小故事（时间线可排序）+ 独立故事库（多角色参与），独立编辑器窗口 + Markdown 实时预览 |
| 图片处理 | 头像 Canvas 圆形裁剪（拖动 + 鼠标锚点缩放），立绘原图保存 |
| 导入导出 | 全量 JSON（可内嵌图片）、单角色卡导出、追加式导入（事务 + ID 重映射） |
| 外观 | 浅色 / 深色 / 跟随系统三主题（浅色为主形态）；浮起外壳 + 背景光晕 + 可调面板通透度，全站 CSS 变量驱动 |
| 交互语言 | 滑动背板（侧栏 / 标签页 / 主题三选）、快出慢进的面板转场、按钮三层反馈、折叠区高度动画、减少动效双闸门 |

## 目录结构

```
.
├── package.json          # 依赖与脚本（start / rebuild / check）
├── main.js               # 主进程：窗口、IPC、图片落盘、导入导出
├── database.js           # 数据层：建表、旧库迁移、CRUD、导入导出
├── preload.js            # contextBridge 白名单（window.api）
├── theme-init.js         # 首屏偏好预加载：主题 / 减少动效 / 面板通透度
├── motion.js             # 动效控制器：面板切换 / 滑动背板 / 弹窗开合 / 共享元素 FLIP
├── index.html            # 主界面：外壳 / 图标精灵 / 工具栏 / 侧栏 / 详情 / 5 个弹窗
├── styles.css            # 颜色与几何令牌 + 动效语汇 + 组件样式
├── renderer.js           # 主窗口全部交互逻辑
├── markdown.js           # Markdown 渲染（marked + DOMPurify）
├── story-editor.html     # 故事编辑器窗口
├── story-editor.js       # 故事编辑器逻辑
├── docs/                 # 工程文档（按工作区块分类）
├── images/               # 角色图片 char_{id}/avatar.* + portrait.*（不进 Git）
├── data/                 # SQLite 数据库 characters.db（不进 Git）
└── node_modules/
```

> `data/` 与 `images/` 是**个人内容**，被 `.gitignore` 排除：仓库里只有程序，没有你的角色。
> 新机器 clone 后首次启动会自动建出这两个目录和一张空表，缺它们不是故障。
> 想在机器之间搬数据，走「导出 / 导入」JSON，别用 Git 传数据库。详见
> [构建与运维 / 仓库卫生](docs/09-构建与运维/01-启动脚本与自检.md#7-仓库卫生)。

文件行数、内部函数索引见 [进程架构与代码地图](docs/00-总览/02-进程架构与代码地图.md)。

## 已知限制

- 关系对象以**姓名字符串**关联，不是外键，改名后需手动同步。
- 故事无全文检索；导入不去重（纯追加）；删除即物理删除，无回收站。
- 冷启动时窗口底色按**系统**深浅取值，若用户手工选了与系统相反的主题，仍会闪约一帧。
- 无自动备份，重要数据请定期用「导出」生成 JSON 快照。

完整清单与改进建议见各区块文档的「已知问题 / 修改指引」小节。
