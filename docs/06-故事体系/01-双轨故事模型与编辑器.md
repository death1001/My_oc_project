# 06-01 · 双轨故事模型与编辑器

## 1. 适用范围

| 层 | 位置 |
| --- | --- |
| 数据 | `database.js` → `stories` / `story_participants`、`createStory` / `updateStory` / `setStoryOrder` / `listGlobalStories` / `listParticipatedStories` |
| 主进程 | `main.js` → `stories:*` 系列 IPC、`createStoryEditorWindow()`、`notifyStoriesSaved()` |
| 渲染层（主窗口） | `renderer.js` → `renderStoriesTab` / `moveStory` / `openStoryEditor` / `openGlobalStoryEditor` / `renderGlobalStoryList` / `selectGlobalStory` / `renderGlobalStoryDetail` / `renderParticipatedSection` / `openStoryReader` / `switchSideView` |
| 编辑器窗口 | `story-editor.html` + `story-editor.js` |

---

## 2. 双轨模型

| 轨道 | `character_id` | 入口 | 排序 | 典型用途 |
| --- | --- | --- | --- | --- |
| 角色小故事 | 非空（FK） | 角色详情 → 小故事 Tab → 撰写新故事 | `sort_order` 时间线，可 ⬆⬇ | 角色成长线、日常片段 |
| 独立故事库 | NULL | 顶部「✍️ 写故事」/ 侧栏「📚 故事」→ ＋写故事 | `updated_at DESC`（固定 0） | 群像、跨角色事件 |

一张表两种语义，好处是编辑器、参与角色、阅读器、导入导出全部共用一套代码；
代价是每个查询都必须显式写 `WHERE character_id IS NULL` 或 `= ?`——**忘记加条件就会把两种故事混在一起**。

## 3. 角色小故事

### 3.1 列表与预览

`renderStoriesTab(c)`（异步）→ `bridge.listStories(c.id)`：

- 每张 `.story-card`：标题、`updated_at`、标签 chip、Markdown 前 160 字预览、四个操作按钮；
- `#storyCount` 同步数量；
- 卡片点击（非按钮区域）默认打开阅读弹窗。

### 3.2 时间线排序

```js
async function moveStory(character, stories, index, dir) {
  const j = index + dir;
  if (j < 0 || j >= stories.length) return;     // 首条上移 / 末条下移：静默忽略
  const arr = stories.slice();
  [arr[index], arr[j]] = [arr[j], arr[index]];
  const r = await bridge.reorderStories(character.id, arr.map(s => s.id));
  if (r && r.ok) renderStoriesTab(character);
  else toast((r && r.error) || '排序保存失败', 'error');
}
```

- 前端交换后把**完整 id 数组**发给主进程（不是「把 A 移到 B 前面」这种相对指令），
  服务端按数组下标重写 `sort_order = 0,1,2…`，实现简单且不会因并发错位；
- 数据库侧 `setStoryOrder` 的 `UPDATE ... WHERE id = ? AND character_id = ?` 双条件，
  防止越权改动其他角色的故事；
- 成功后重新拉取列表（而不是本地重排 DOM），保证与数据库一致。

### 3.3 新建时自动追加末尾

```sql
SELECT COALESCE(MAX(sort_order), -1) + 1 AS next FROM stories WHERE character_id = ?
```

`COALESCE` 保证空集时得到 0，不会返回 NULL。

## 4. 独立故事库

### 4.1 侧栏视图切换

`switchSideView('chars' | 'stories')`：

```
切到 stories：
  侧栏按钮高亮 → 显示 #storiesView / 隐藏 #charsView
  applyLayout()            // 卡片布局失效，侧栏回 280px
  隐藏 #detail（角色详情）
  renderGlobalStoryList()
  有 currentGlobalStoryId 则重新选中，否则 showGlobalStoryEmpty()

切回 chars：
  隐藏 #globalStoryDetail，显示 #detail
  有 currentId 则 renderDetail，否则 showEmptyDetail()
```

**两个详情区不是同一个容器**：`#detail`（角色）与 `#globalStoryDetail`（故事），
切换视图时整块互换，避免状态互相污染。

### 4.2 列表与详情

- `renderGlobalStoryList()` → `bridge.listGlobalStories()`，按更新时间倒序，显示标题、时间、参与角色摘要；
- `selectGlobalStory(id)` → `bridge.getGlobalStory(id)` → 缓存到 `state.globalStoryCache` → `renderGlobalStoryDetail()`；
- 详情：标题、标签 chip、创建/更新时间、Markdown 正文、参与角色卡、三个按钮（返回/编辑/删除）；
- 删除用 `showConfirm()` 自定义确认框，确认后 `deleteStory` → 刷新列表 → `showGlobalStoryEmpty()`。

### 4.3 参与角色

| 环节 | 实现 |
| --- | --- |
| 编辑器中选人 | `story-editor.js` → `loadAllCharacters()`、`renderParticipantOptions()`（搜索 + 排除已选）、`renderParticipantChips()`（chip + ✕ 移除） |
| 保存 | `data.participantIds = selectedParticipants.map(c => c.id)`；`updateStory` 时若带该字段则**整体覆盖**关联表 |
| 展示 | `renderParticipantCards()`：按姓名排序的 3:4 立绘卡，点击 `jumpToCharacterById()` 跳角色 |
| 反向查询 | 角色详情「参与的故事」区：`renderParticipatedSection(c)` → `listParticipatedStories(c.id)` |

参与角色的选择对**两种故事都可用**——角色小故事也能标注「同场的其他角色」，不限于独立故事。

## 5. 故事编辑器窗口

### 5.1 打开方式

```js
// 角色小故事
openStoryEditor(mode, characterId, characterName, story)
  → bridge.openStoryEditor({ mode, characterId, characterName, story })

// 独立故事
openGlobalStoryEditor(mode, story)
  → bridge.openStoryEditor({ mode, characterId: null, characterName: '', isGlobal: true,
                             story, participants: story.participants || [] })
```

主进程 `createStoryEditorWindow(payload)`：

- 窗口已存在 → `webContents.send('editor:payload', payload)` + `focus()`，**不新建**；
- 不存在 → 新建 1060×860 窗口，把 payload 挂到 `storyEditorWin._editorPayload`，
  加载 `story-editor.html`；
- 编辑器启动时 `bridge.getEditorPayload()` 通过 `BrowserWindow.fromWebContents(event.sender)`
  取自己窗口上的 payload。

### 5.2 编辑器内部

| 功能 | 实现 |
| --- | --- |
| 标题 / 正文 / 标签 | `#f_title` / `#f_content` / `#f_tags` |
| 编辑 ↔ 预览 | `setMode()` 切换 `hidden`，按钮文案在「预览 / 编辑」间变化 |
| 实时预览 | `#f_content` 的 `input` → `updatePreview()` → `window.MD.render()` |
| 参与角色 | 搜索框 `#f_participant_search` + 候选按钮 + 已选 chip |
| 保存 | 标题必填校验；`payload.mode === 'edit'` 走 `updateStory`，否则 `createStory`（`character_id` 为 `null` 即独立故事） |
| 保存后 | toast「已保存」→ 500ms 后 `window.close()`；主窗口已通过 `stories:saved` 自动刷新 |
| 删除 | 仅编辑态显示 `#btnDelete`；用原生 `window.confirm`（子窗口未引入主窗口的自定义确认框） |
| 异常上下文 | 拿不到 payload → 显示 `#err`「未获取到编辑数据」，隐藏主区域 |

### 5.3 刷新联动

```
编辑器 save/delete
   → IPC handler
   → db 写入
   → notifyStoriesSaved(characterId, isGlobal)
   → mainWindow.webContents.send('stories:saved', {...})
   → 主窗口 onStoriesSaved → 刷新详情 / 列表
```

所以编辑器不需要告诉主窗口「刷新哪个区域」，主窗口按 `characterId` / `isGlobal` 自己判断。

## 6. 阅读弹窗

`openStoryReader(story, character)`：标题、`角色：xxx`、标签 + 创建/更新时间、Markdown 正文、参与角色卡。

- 数据来自列表项（`listStories` 已附 `participants`），无需再请求；
- `readerState` 保存当前故事与角色，供弹窗底部「编辑 / 删除」按钮使用；
- `closeStoryReader()` 清空状态并隐藏。

## 7. 修改指引

| 需求 | 步骤 |
| --- | --- |
| 故事加字段（如「章节」） | `CREATE_SQL` + 迁移 + `createStory`/`updateStory` 字段白名单 + 编辑器表单 + 详情渲染 + 导出 |
| 改为富文本编辑器 | 需替换 `#f_content` 的 textarea 与 `updatePreview()`，并决定存储格式（HTML 还是 Markdown） |
| 独立故事也支持排序 | `listGlobalStories` 改 `ORDER BY sort_order`，新建时不再固定 0，再接入 `stories:reorder` |
| 参与角色支持排序 / 角色定位 | `story_participants` 加 `role` 列，chip 与卡片显示 |
| 编辑器支持多开 | 改 `createStoryEditorWindow` 的单例逻辑 + payload 存储方式 |
| 用自定义确认框替换 `window.confirm` | `story-editor.js` 的 `remove()`，需把主窗口的 `showConfirm` 搬进子窗口或抽公共文件 |

## 9. 验证方式

| 检查项 | 操作 | 预期 |
| --- | --- | --- |
| 新建角色小故事 | 角色详情 → 撰写新故事 → 填标题保存 | 编辑器 500ms 后关闭，主窗口小故事 Tab 出现新卡片（末尾） |
| 时间线排序 | 点第 2 条的 ⬆ | 两条互换，重开应用顺序仍保持（`sort_order` 已落库） |
| 窗口复用 | 不关编辑器，回主窗口点另一条「编辑」 | 仍是同一个编辑器窗口，内容切换 |
| 独立故事 | 顶部「写故事」→ 选 2 个参与角色 → 保存 | 侧栏故事视图出现该故事，详情底部显示 2 张参与角色卡 |
| 反向查询 | 打开其中一个参与角色的详情 | 「参与的故事」区列出该独立故事，点击可跳转 |
| 联动刷新 | 删除故事后回主窗口 | 列表与详情自动更新，无需手动刷新 |
| 直接打开 HTML | 双击 `story-editor.html` | 显示「未获取到编辑数据」而不是白屏崩溃 |
