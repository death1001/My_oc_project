# 02-01 · 窗口生命周期与单实例

## 1. 适用范围

- `main.js` → `createWindow()` / `createStoryEditorWindow()` / 文件末尾的生命周期块
- 变量：`mainWindow`、`storyEditorWin`

---

## 2. 主窗口

```js
new BrowserWindow({
  width: 1440, height: 920,          // 默认尺寸
  minWidth: 1120, minHeight: 700,    // 小于此尺寸侧栏 + 详情会挤坏布局
  title: '角色资料查询器',
  autoHideMenuBar: true,             // 隐藏默认菜单栏（Alt 可临时唤出）
  backgroundColor: '#171a21',        // 深色底，避免加载瞬间白闪
  webPreferences: {
    preload: path.join(__dirname, 'preload.js'),
    contextIsolation: true,
    nodeIntegration: false
  }
});
mainWindow.loadFile(path.join(__dirname, 'index.html'));
mainWindow.on('closed', () => { mainWindow = null; });
```

- `backgroundColor` **写死深色**：主进程拿不到 localStorage，无法在建窗口时知道用户选的浅色主题。
  这是已知瑕疵 → 浅色主题用户启动时会看到一帧深色。修复思路见第 6 节。
- 关闭后把引用置 `null`，防止 `webContents.send` 打到已销毁对象上。

## 3. 故事编辑器窗口（单例复用）

```js
if (storyEditorWin && !storyEditorWin.isDestroyed()) {
  storyEditorWin.webContents.send('editor:payload', payload);
  storyEditorWin.focus();
  return;                       // 不新建，只推新上下文
}
storyEditorWin = new BrowserWindow({ width: 1060, height: 860,
  minWidth: 800, minHeight: 640, ...同主窗口的 webPreferences });
storyEditorWin._editorPayload = payload;   // 挂在窗口对象上，供 IPC 读取
storyEditorWin.loadFile(path.join(__dirname, 'story-editor.html'));
storyEditorWin.on('closed', () => { storyEditorWin = null; });
```

**为什么挂在窗口对象上**：编辑器页面加载完后要问「我这次编辑什么」，
`stories:getEditorPayload` 用 `BrowserWindow.fromWebContents(event.sender)` 找到发起窗口，
读它自己的 `_editorPayload`。这样两个窗口各存各的上下文，不会串。

**复用而非新建**：避免用户连续点开多个故事时堆一堆窗口；复用后通过 `editor:payload` 事件
让编辑器自己 `fillForm()` 换内容。

## 4. 单实例锁

```js
const gotLock = app.requestSingleInstanceLock();
if (!gotLock) {
  app.quit();                       // 第二实例：直接退出
} else {
  app.on('second-instance', () => {  // 第一实例：把已有窗口叫到前面
    if (mainWindow) {
      if (mainWindow.isMinimized()) mainWindow.restore();
      mainWindow.focus();
    }
  });
  ...
}
```

**必要性**：两个进程同时写同一个 SQLite 文件会互相阻塞甚至损坏（WAL 模式下虽能并发，
但业务上仍是同一份数据被两个 UI 编辑，极易出现覆盖）。单实例锁是最省事的防线。

**副作用（重要）**：如果第一实例启动后**没有窗口却仍存活**，它会一直占着锁，
用户之后每次双击都走 `app.quit()` 分支 → 表现为「点了完全没反应」。
v1.1 的「快捷方式打不开」故障正是这条链路，因此加了启动兜底（见下）。

## 5. 启动兜底（v1.1 新增）

```js
app.whenReady().then(() => {
  try {
    db.initDatabase();
  } catch (err) {
    dialog.showErrorBox('启动失败',
      '数据库初始化失败：\n' + err.message +
      '\n\n常见原因：better-sqlite3 原生模块缺失或 ABI 不匹配。\n请在项目目录执行：npm run rebuild');
    app.quit();          // 关键：显式退出，释放单实例锁
    return;              // 不再 registerIpc / createWindow
  }
  registerIpc();
  createWindow();
  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow();
  });
});
```

设计要点：

1. **必须 `app.quit()`**：不退出就会复现「无窗口占锁」；
2. **必须在 `createWindow()` 之前**：数据库不可用时开窗口也没意义，还会让用户以为软件正常但功能全废；
3. **错误文案要可执行**：直接给出 `npm run rebuild`，减少用户排查成本。

## 6. 退出与激活

```js
app.on('window-all-closed', () => { app.quit(); });   // Windows：关完窗口就退出
```

- macOS 惯例是保留进程，但本项目只面向 Windows，简化为直接退出。
- `activate` 事件用于「关完窗口后点任务栏图标」的兜底重建（Windows 上极少触发，保留无害）。

## 7. 修改指引

| 需求 | 位置 |
| --- | --- |
| 改默认窗口大小 / 最小尺寸 | `createWindow()` 的 `width/height/minWidth/minHeight` |
| 消除浅色主题的启动闪屏 | 把主题偏好落到 `data/ui-prefs.json`，在 `new BrowserWindow` **之前**同步读，决定 `backgroundColor` |
| 编辑器窗口允许开多个 | 去掉 `storyEditorWin` 单例判断，改为数组管理 + 关闭时移除 |
| 启动前做更多自检（如目录可写） | 放进 `whenReady` 的 try 块，失败同样 `showErrorBox` + `quit` |

| 版本 | 变更 |

| v1.0 | 主窗口 + 编辑器单例窗口、单实例锁、`window-all-closed` 退出 |

## 9. 验证方式

- 单实例：应用运行中再次双击快捷方式 → 不出现第二个窗口，原窗口获得焦点。
- 兜底：临时把 `better_sqlite3.node` 改名 → 启动应弹「启动失败」错误框，关闭后进程消失
  （任务管理器无 `electron.exe` 残留），恢复文件名后再次启动正常。
- 窗口复用：连续点开两个故事 → 只有一个「小故事编辑器」窗口，内容切换为后点的故事。
