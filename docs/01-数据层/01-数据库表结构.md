# 01-01 · 数据库表结构

## 1. 适用范围

- 建表语句：`database.js` → `CREATE_SQL` 常量（第 26–73 行）
- 初始化：`initDatabase()` / `getDb()` / `ensureDirs()`
- 序列化：`CHAR_FIELDS` / `serializeChar()` / `rowToCharacter()`
- 数据库文件：`data/characters.db`（路径见 `database.js` 顶部 `DB_PATH`）

---

## 2. 库级设置

```js
const db = new Database(DB_PATH);
db.pragma('journal_mode = WAL');   // 写不阻塞读，异常退出更安全
db.pragma('foreign_keys = ON');    // 级联删除依赖此开关，必须开
```

- `ensureDirs()` 在启动时确保 `data/` 与 `images/` 存在，缺失则创建。
- 单文件数据库，无服务器进程，备份即复制文件（WAL 模式下建议连 `-wal` / `-shm` 一起拷，或先退出应用）。

---

## 3. characters — 角色主表（20 列）

| 列 | 类型 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `id` | INTEGER PK AUTOINCREMENT | — | 主键，**同时决定图片目录名** `images/char_{id}/` |
| `name` | TEXT NOT NULL | `''` | 姓名，列表与详情的主标识 |
| `alias` | TEXT | `''` | 别名称号，参与搜索匹配 |
| `age` | INTEGER | NULL | 年龄，可为空（非人类/未知） |
| `gender` | TEXT | `''` | 性别，自由文本 |
| `race` | TEXT | `''` | 种族，同时作为筛选维度 |
| `birth_date` | TEXT | `''` | 出生年月，自由文本（支持「星历 302 年」这类设定） |
| `birth_place` | TEXT | `''` | 出生地点 |
| `affiliation` | TEXT | `''` | 阵营 / 组织，作为筛选维度与卡片角标 |
| `profession` | TEXT | `''` | 身份 / 职业 |
| `personality` | TEXT | `''` | 性格，逗号分隔，渲染为 chip 标签 |
| `abilities` | TEXT(JSON) | `'[]'` | `[{ name, description, level }]` |
| `weapons` | TEXT(JSON) | `'[]'` | `[{ name, type, description }]` |
| `combat_stats` | TEXT(JSON) | `'{}'` | `{ "hp": 100, "attack": 80 }`，值为数字时会转 Number |
| `relationships` | TEXT(JSON) | `'{}'` | `{ family:[], companions:[], rivals:[], mentors:[] }`，每项 `{ name, description }` |
| `metadata` | TEXT(JSON) | `'{}'` | `{ work, first_appearance, rarity, tags:[] }` |
| `avatar_path` | TEXT | `''` | 头像相对路径，空串 = 无图 |
| `portrait_path` | TEXT | `''` | 立绘相对路径，空串 = 无图 |
| `created_at` / `updated_at` | TEXT | `datetime('now','localtime')` | 本地时间字符串，列表按 `updated_at DESC, id DESC` 排序 |

**为什么 JSON 内联而不建子表**：这些字段是「整体读写、不参与跨角色查询」的附属数据，
内联后一次 `SELECT` 就能拿全一个角色的所有信息，省掉 5 次 JOIN 与对应的组装代码。
代价是无法用 SQL 直接查「谁会火球术」——需要时在应用层过滤。

---

## 4. stories — 故事表（双轨制，8 列）

| 列 | 类型 | 语义 |
| --- | --- | --- |
| `id` | INTEGER PK AUTOINCREMENT | 主键 |
| `character_id` | INTEGER NULL | **NULL = 独立故事（故事库）**；非空 = 该角色的专属小故事 |
| `title` | TEXT NOT NULL | 标题 |
| `content` | TEXT | Markdown 正文 |
| `tags` | TEXT | 逗号分隔标签 |
| `sort_order` | INTEGER DEFAULT 0 | 角色小故事的时间线顺序（越小越靠前）；独立故事固定 0 |
| `created_at` / `updated_at` | TEXT | 时间戳 |

外键：`FOREIGN KEY (character_id) REFERENCES characters(id) ON DELETE CASCADE`
→ 删除角色时其小故事自动删除。

**一张表承载两种故事的原因**：两者字段完全相同，只有「归属」不同。
用可空外键区分，避免两套表 + 两套 CRUD + 两套导入导出分支。

---

## 5. story_participants — 故事参与关系（多对多）

| 列 | 类型 | 语义 |
| --- | --- | --- |
| `story_id` | INTEGER NOT NULL | 指向 `stories.id` |
| `character_id` | INTEGER NOT NULL | 指向 `characters.id` |

- 复合主键 `(story_id, character_id)`，天然去重。
- 两个外键均 `ON DELETE CASCADE`：删故事清关联，删角色也清关联。
- 用途：一个故事标注多个参与角色；角色详情页据此反向查询「该角色参与的故事」。

---

## 6. 索引

| 索引 | 目标 | 服务场景 |
| --- | --- | --- |
| `idx_stories_character` | `stories(character_id)` | 按角色取小故事列表 |
| `idx_story_participants_character` | `story_participants(character_id)` | 反向查「某角色参与的故事」 |

`characters` 表数据量小（通常几十到几百行），列表查询走全表扫描即可，未建额外索引。

---

## 7. 序列化契约

`CHAR_FIELDS`（`database.js`）是**唯一字段白名单**，决定哪些键会写库：

```
name, alias, age, gender, race, birth_date, birth_place,
affiliation, profession, personality,
abilities, weapons, combat_stats, relationships, metadata,
avatar_path, portrait_path
```

- 写：`serializeChar(data)` → JSON 字段 `JSON.stringify`，缺失字段填默认值；
- 读：`rowToCharacter(row)` → JSON 字段 `parseJSON`，解析失败回退为空结构。

**新增字段时必须同步改三处**：`CREATE_SQL`、`CHAR_FIELDS`、`serializeChar()` / `rowToCharacter()`；
已存在的库还需补一条 `ALTER TABLE` 迁移（见 [02-初始化迁移与CRUD](02-初始化迁移与CRUD.md)）。

## 9. 验证方式

```bash
# 用 Electron 运行时读（系统 Node 会因 ABI 不匹配失败）
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe -e "
const D=require('better-sqlite3');
const d=new D('data/characters.db',{readonly:true});
console.log(d.prepare('select name from sqlite_master where type=\"table\"').all());
console.log(d.prepare('pragma table_info(characters)').all().map(c=>c.name).join(','));
console.log('chars', d.prepare('select count(*) c from characters').get().c,
            'stories', d.prepare('select count(*) c from stories').get().c);
"
```

预期：3 张业务表（另有 `sqlite_sequence`）+ 2 个索引；`characters` 列为上述 20 列。
