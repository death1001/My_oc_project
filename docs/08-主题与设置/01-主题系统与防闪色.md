# 08-01 · 主题系统与防闪色

## 1. 适用范围

| 层 | 位置 |
| --- | --- |
| 预加载 | `theme-init.js`（109 行）——**必须第一个执行** |
| 变量定义 | `styles.css` → `:root`（**浅色，主形态**）与 `html[data-theme="dark"]`（暗色覆盖） |
| 使用方 | `renderer.js`（`syncSettingsUI` / `setTheme`）、`story-editor.html`（同样引入脚本） |
| 存储 | `localStorage['clw:theme']` = `light` \| `dark` \| `system`；另有两份偏好共用本文件（见 §4.5） |

---

## 2. 核心机制：只切属性，不切样式表

```
theme-init.js  →  写 <html data-theme="light|dark">  +  data-theme-pref="light|dark|system"
styles.css     →  :root { …浅色变量… }      html[data-theme="dark"] { …暗色覆盖… }
组件样式        →  只用 var(--xxx)，从不写死颜色
```

> v2.0 起**浅色是主形态**：`:root` 放浅色，暗色只覆盖变量。原因是暗色把
> `--accent` 反转成灰白（`#f0f0f2`），若把它放在 `:root`，任何漏写的组件都会
> 出现"白底白字"；让默认值落在浅色，漏写最多是"白底蓝字"，仍可读。

优点：

- 一套组件样式，两套配色，不会出现「深色改了、浅色忘了」的双份维护；
- 加第三套主题（如「羊皮纸」）只需再写一个 `html[data-theme="paper"] { … }` 变量块；
- 所有颜色集中在一个文件顶部，改配色不用翻 1300 行样式。

**硬约束**：新增颜色必须先在两个变量块里定义，再在组件里 `var()` 引用。
直接写 hex 会导致另一套主题下该元素保持原色（历史上有 15 处这类硬编码，v1.3 已清理；
v2.0 复查后仅剩"压在照片上的叠加层"两处，属有意为之）。

---

## 3. 时序：为什么需要 `theme-init.js`

```
浏览器解析 <head>
  ① <script src="theme-init.js">   同步执行 → 读 localStorage → 设置 data-theme
  ② <link rel="stylesheet">        此时 CSS 已能用正确的 data-theme 匹配变量
  ③ <body> 渲染                     首帧即正确主题，无闪色
```

对比常见错误做法：把主题逻辑放在 `DOMContentLoaded` 或 `renderer.js` 里 →
CSS 先按默认深色渲染一帧，脚本执行后才变浅色，**肉眼可见闪一下**（FOUC）。

因为 CSP 是 `script-src 'self'`（禁止内联脚本），无法把这段代码直接写进 `<head>`，
只能单独建文件——这就是 `theme-init.js` 存在的原因。

## 4. 脚本逻辑

```js
const KEY = 'clw:theme';
const mql = window.matchMedia('(prefers-color-scheme: dark)');

function getPref() {              // 读偏好，非法值回退 'system'
  try {
    const v = localStorage.getItem(KEY);
    if (v === 'light' || v === 'dark' || v === 'system') return v;
  } catch (_) {}
  return 'system';
}

function resolve(pref) {          // 偏好 → 实际主题
  return pref === 'system' ? (mql.matches ? 'dark' : 'light') : pref;
}

function apply(pref) {            // 写 DOM 属性
  const p = pref || getPref();
  const actual = resolve(p);
  root.setAttribute('data-theme', actual);
  root.setAttribute('data-theme-pref', p);
  return actual;
}

apply();                          // 首屏立即生效

const onSchemeChange = () => { if (getPref() === 'system') apply('system'); };
mql.addEventListener?.('change', onSchemeChange) ?? mql.addListener?.(onSchemeChange);

window.Theme = {
  get: getPref,
  resolve,
  set(pref) { localStorage.setItem(KEY, pref); return apply(pref); },   // 返回实际主题
  current() { return document.documentElement.getAttribute('data-theme'); }
};
```

### 三个属性 / 方法的分工

| 接口 | 返回 | 用途 |
| --- | --- | --- |
| `data-theme` | `light` / `dark` | CSS 匹配变量块；**只有实际主题** |
| `data-theme-pref` | `light` / `dark` / `system` | 记住用户原意；`system` 时界面要显示「跟随系统（当前X）」 |
| `Theme.get()` | 偏好值 | 设置面板高亮哪一项 |
| `Theme.current()` | 实际主题 | 提示文案里的「当前浅色/深色」 |
| `Theme.set(pref)` | 实际主题 | 保存并应用，返回解析结果 |

### 跟随系统的实时响应

`matchMedia('(prefers-color-scheme: dark)')` 的 `change` 事件在系统切换深/浅色时触发。
**只在偏好为 `system` 时才重算**——用户明确选了「浅色」时不应该被系统改掉。

同时 `renderer.js` 的 `bindEvents()` 里也监听了一次，用来刷新设置面板上的文字提示
（`syncSettingsUI()`），两处监听互不冲突：一个改样式，一个改文案。

### 4.5 同一个文件还管另外两份偏好

v2.0 起 `theme-init.js` 不只管主题，还负责两项**必须首屏生效**的偏好——
它们的解析规则只能有一处，否则设置面板与首屏会打架：

| key | 作用 | 落地方式 |
| --- | --- | --- |
| `clw:reduceMotion` = `'1'`/`'0'` | 应用内「减少动效」 | `html.reduce-motion`（CSS 闸 1） |
| `clw:panelOpacity` = `55`–`100` | 面板通透度 | `--panel-opacity`（外壳 `--panel-bg` 引用） |

`window.Theme` 因此扩展出 `getReduceMotion / setReduceMotion / getPanelOpacity / setPanelOpacity`。
细节见 `08-02 §3`。

## 5. 与设置面板的衔接

```js
function setTheme(pref) {
  if (!window.Theme) return;
  window.Theme.set(pref);      // 写 localStorage + 改 data-theme
  syncSettingsUI();            // 更新分段控件高亮与提示文案
  toast('主题已切换为' + THEME_LABELS[pref]);
}

function syncSettingsUI() {
  const pref = window.Theme.get();
  $$('#segTheme .seg-item').forEach(b => b.classList.toggle('active', b.dataset.value === pref));
  const actual = window.Theme.current();
  hint.textContent = pref === 'system'
    ? '跟随系统（当前' + (actual === 'light' ? '浅色' : '深色') + '）'
    : '当前' + THEME_LABELS[pref];
}
```

主题切换是**同步立即生效**的：改 `data-theme` → 浏览器重算样式，无需重新加载页面。

## 6. 两个窗口共享主题

`index.html` 与 `story-editor.html` 的 `<head>` 都引入了 `theme-init.js`：

```html
<script src="theme-init.js"></script>
<link rel="stylesheet" href="styles.css">
```

两个窗口同源（同一个 `file://` 目录），`localStorage` 共享，所以主窗口切浅色后
新打开的编辑器窗口也是浅色。**但已打开的编辑器窗口不会自动跟随**——
需要在主窗口 `setTheme()` 时通过 IPC 通知，或让编辑器自己监听 `storage` 事件。
当前未实现（编辑器通常在几秒内关闭，影响很小）。

## 7. 启动瞬间的深色闪屏（v2.0 已减轻）

`main.js` 的 `BrowserWindow` 配置原来写死深色：

```js
backgroundColor: '#171a21'   // 主进程拿不到 localStorage
```

Electron 在页面加载完成前会先铺这个背景色，浅色主题用户在冷启动时会看到一帧深色，
页面内的防闪色脚本管不到这一层（它是原生窗口背景，不是 DOM）。

v2.0 改成按系统深浅取近似值：

```js
function shellBg() {
  return nativeTheme.shouldUseDarkColors ? '#18181b' : '#eef3fd';
}
```

- **跟随系统（默认）**：完全准确，不再闪；
- **用户手工选了与系统相反的主题**：仍会有约一帧偏差（冷启动时读不到 localStorage）。

彻底修复需要主进程参与偏好读写：主题偏好额外写一份 `data/ui-prefs.json`，
`main.js` 在 `new BrowserWindow` 之前同步 `fs.readFileSync`，按 `pref` 解析后决定底色。
代价是主进程要处理文件不存在/损坏的兜底，当前未做。

## 8. 修改指引

| 需求 | 做法 |
| --- | --- |
| 加第三套主题 | ① `styles.css` 加 `html[data-theme="xxx"] { …完整变量覆盖… }`；② `theme-init.js` 的 `getPref` 白名单加值；③ 设置面板加一个 `.seg-item[data-value="xxx"]`；④ `THEME_LABELS` 加文案 |
| 改某个颜色 | 只改两个变量块里对应的 `--xxx`，不要在组件里写 hex |
| 让系统主题变化也影响「浅色/深色」固定选择 | 改 `onSchemeChange` 的判断（不建议，违背用户明确选择） |
| 消除启动闪屏 | 见第 7 节方案 |
| 让编辑器窗口实时跟随 | 主窗口 `setTheme` 时 `webContents.send('theme:changed', pref)`，编辑器监听后调 `Theme.set()` |

## 10. 验证方式

```js
// 1. 切换并检查实际颜色
window.Theme.set('light');
document.documentElement.dataset.theme;                        // 'light'
getComputedStyle(document.body).backgroundColor;               // 'rgb(238, 243, 253)'  #eef3fd
getComputedStyle(document.body).color;                         // 'rgb(22, 35, 61)'     #16233d
getComputedStyle(document.querySelector('.btn-primary')).backgroundColor;  // 'rgb(59, 111, 224)'

window.Theme.set('dark');
getComputedStyle(document.body).backgroundColor;               // 'rgb(24, 24, 27)'     #18181b
getComputedStyle(document.querySelector('.btn-primary')).backgroundColor;  // 'rgb(240, 240, 242)'（白底）
getComputedStyle(document.querySelector('.btn-primary')).color;            // 'rgb(37, 37, 43)'  （深字）

// 2. 跟随系统
window.Theme.set('system');
document.documentElement.dataset.themePref;                    // 'system'
window.Theme.current();                                        // 'dark' | 'light'

// 3. 持久化
localStorage.getItem('clw:theme');

// 4. 无闪色（人工）：清 localStorage → 设 light → 重启应用，观察首帧
```

> 切换主题后立刻读计算样式会读到**过渡中间值**（`.btn` 的 `background-color`
> 有 140ms 过渡）。要验证终值请 `await` 200ms 以上。

样式审计（改完配色后必跑）：

```bash
grep -nE "#[0-9a-fA-F]{6}" styles.css | grep -v "^\s*--" | head -20
# 除 :root / html[data-theme] 两个变量块外，理论上不应有裸 hex
```
