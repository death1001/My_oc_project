# 00-01 · 项目概览与技术栈

## 1. 项目定位

**角色资料查询器**（`package.json` 中 `name: character-library`、`productName: 角色资料查询器`）是一个
**纯本地、离线运行**的 Windows 桌面应用，面向小说 / 企划 / 跑团 / 同人创作者。

核心诉求：把散落在文档、表格、聊天记录里的角色设定，收敛成一份**可检索、可关联、可导出**的结构化档案。

数据只存在本地两处，不连任何网络服务：

| 位置 | 内容 |
| --- | --- |
| `data/characters.db` | SQLite 单文件数据库（WAL 模式） |
| `images/char_{角色ID}/` | 该角色的 `avatar.*`（头像）与 `portrait.*`（立绘） |

---

## 2. 技术选型

| 层次 | 选型 | 版本 | 选它的理由 |
| --- | --- | --- | --- |
| 桌面容器 | Electron | `^33.4.0`（实际 33.4.11） | 需要多窗口（主窗口 + 故事编辑器）与本地文件读写，纯前端做不到 |
| 数据存储 | better-sqlite3 | `^11.10.0` | 同步 API，无需 Promise 编排；单文件便于备份与迁移；原生模块性能足够 |
| Markdown | marked | `^4.3.0` | 故事正文用 Markdown 撰写，需要 GFM 支持 |
| HTML 消毒 | DOMPurify | `^3.2.4` | marked 输出的是 HTML 字符串，直接插 DOM 有 XSS 风险 |
| 界面 | 原生 HTML / CSS / JS | — | 无构建步骤，改完存盘即生效；避免为一个本地小工具引入框架与打包链 |
| 图标 / 图形 | 手写 SVG | — | 关系网络需要按数据动态生成，画布库反而增加约束 |

**没有的东西**（刻意保持简单）：前端框架、打包器、TypeScript、状态管理库、图表库、UI 组件库、单元测试框架。
因此源码即产物：`npm start` 直接以 Electron 加载 `index.html`。

---

## 3. 能力清单

按用户可见功能划分：

1. **角色档案** — 20 个字段的完整档案（姓名/别名、年龄性别种族、出生、阵营职业、性格、能力、武器、战斗属性、四类关系、作品/初登场/稀有度/标签、头像与立绘）。
2. **三种列表布局** — 列表 / 网格卡片墙 / 紧凑网格，可在设置中切换并记忆。
3. **搜索与筛选** — 姓名+别名模糊搜索，阵营 / 种族 / 标签三维组合筛选。
4. **关系网络** — 纯 SVG 径向图，四类关系四色连线，点击节点按姓名跳转。
5. **双轨故事体系** — 角色专属小故事（支持时间线排序）与跨角色独立故事库（支持多角色参与）。
6. **故事编辑器** — 独立子窗口，Markdown 编辑 + 实时预览。
7. **头像裁剪** — Canvas 圆形裁剪，支持拖动、以鼠标为中心缩放。
8. **导入导出** — 全量 JSON（可内嵌图片 base64）、单角色卡导出、追加式导入。
9. **外观设置** — 浅色 / 深色 / 跟随系统三主题，全站 CSS 变量驱动。
10. **安全基线** — 进程隔离 + preload 白名单 + CSP + 输出转义。

## 4. 运行形态

```
Windows 桌面应用（单实例）
├── 主窗口  1440×920（最小 1120×700）  index.html
└── 子窗口  1060×860（最小 800×640）  story-editor.html（复用，单例）
```

- 关闭全部窗口即退出进程（`window-all-closed` → `app.quit()`）。
- 重复启动只聚焦已有窗口，不会开第二个实例。
- 无自动更新、无遥测、无后台常驻。

## 7. 验证方式

- 技术栈核对：读 `package.json` 的 `dependencies` / `devDependencies`。
- 运行形态核对：`main.js` 中 `createWindow()` 与 `createStoryEditorWindow()` 的 `BrowserWindow` 参数。
- 离线性核对：全项目 `grep -n "http" ` 应只命中 `pathToFileURL` 与 CSP / 文档链接，无运行时网络请求。
