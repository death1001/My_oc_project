# 00-02 · 进程架构与代码地图

## 1. 三层进程模型

```
┌──────────────────────────── 主进程 (main.js) ────────────────────────────┐
│ 应用生命周期 · 单实例锁 · 窗口创建（main / story-editor）                  │
│ IPC 注册 registerIpc()：21 个 handler，统一 wrap() → {ok, data|error}      │
│ 图片落盘 saveImageFromSource / saveImageFromDataUrl / clearImageSlot       │
│ 导入导出（dialog 选文件 + fs 读写）                                        │
└──────────┬───────────────────────────────────────────┬───────────────────┘
           │ require                       ipcMain.handle / webContents.send
   ┌───────▼─────────┐                        ┌────────▼─────────┐
   │ database.js     │                        │ preload.js       │
   │ SQLite 封装      │                        │ contextBridge    │
   │ 建表/迁移/CRUD   │                        │ window.api 白名单 │
   │ 导入导出逻辑     │                        └────────┬─────────┘
   └───────┬─────────┘                                 │ window.api.*
           │ better-sqlite3                    ┌───────▼──────────────────┐
   ┌───────▼──────────────┐                     │ 渲染进程（无 Node 权限）   │
   │ data/characters.db   │                     │ index.html + renderer.js │
   │ images/char_{id}/    │                     │ story-editor.html + .js  │
   └──────────────────────┘                     │ markdown.js / motion.js  │
                                                │ theme-init.js（head 前置）│
                                                └──────────────────────────┘
```

**三条硬边界**

1. 渲染进程 `nodeIntegration: false` + `contextIsolation: true`，无法 `require`，只能调 `window.api`。
2. 所有数据库操作只在主进程发生；渲染层拿到的永远是纯 JS 对象。
3. 主进程从不主动读渲染层状态；需要通知时用 `webContents.send`（`stories:saved` / `editor:payload`）。

## 2. 模块依赖关系

```
main.js
 ├── electron (app, BrowserWindow, ipcMain, dialog)
 ├── database.js  ← 唯一数据入口
 └── fs / path / url

preload.js
 └── electron (contextBridge, ipcRenderer)

database.js
 ├── better-sqlite3
 └── fs / path

renderer.js   （浏览器上下文）
 ├── window.api  （来自 preload）
 ├── window.MD   （来自 markdown.js）
 └── window.Theme（来自 theme-init.js）

story-editor.js（浏览器上下文）
 ├── window.api
 ├── window.MD
 └── window.Theme
```

依赖是**单向**的：`renderer` 不知道 `database` 的存在，`database` 不知道窗口的存在。

## 5. 关键设计约定

1. **同步数据层**：`database.js` 全同步，不返回 Promise；渲染层的 async 只来自 IPC。
2. **统一返回包**：所有 IPC 结果为 `{ ok:true, data }` 或 `{ ok:false, error }`，渲染层只判 `ok`，
   不在渲染层写 try/catch 兜底（除 JSON 解析等本地逻辑）。
3. **JSON 内联字段**：能力 / 武器 / 战斗属性 / 关系 / 元信息不建子表，以 TEXT 存 JSON，
   由 `serializeChar()` / `rowToCharacter()` 双向转换。
4. **图片存相对路径**：库里存 `images/char_3/portrait.png`，取图时由主进程转 `file://` 并附加 `?t=mtime`。
5. **状态集中在 `state`**：渲染层只有一个全局状态对象，改完调对应 `renderXxx()` 重绘，
   没有订阅机制，也没有虚拟 DOM。

## 7. 验证方式

- 边界验证：开发者工具 Console 执行 `typeof require` 应得 `undefined`，`typeof window.api` 应得 `object`。
- 依赖方向验证：`grep -n "database" renderer.js` 应无结果。
- 结构验证：`grep -n "^function " renderer.js` 与本文件第 4 节表格比对。
