# 03 · 功能说明书

> 这是给**使用者**看的手册：每个按钮做什么、数据存在哪、出问题怎么自救。
> 想知道"怎么实现的"，去对应区块的开发文档（索引见 [`docs/README.md`](../README.md)）。
> 本文对应版本 **v2.0.2**。

---

## 1. 一分钟上手

| 步骤 | 操作 |
| --- | --- |
| 1 | 双击桌面的「角色资料查询器」（或在项目目录 `npm start`） |
| 2 | 点右上角 **新建角色** → 至少填「姓名」→ 选头像 / 立绘 → **保存** |
| 3 | 左侧列表点一个角色，右侧展开档案 |
| 4 | 写故事：详情里切到「小故事」标签 → **撰写新故事** → 保存 |
| 5 | 换外观：右上角齿轮 → 主题 / 布局 / 动效 / 通透度 |

首次启动会在程序目录自动创建 `data/`（数据库）、`images/`（图片）两个文件夹和一张空表。
**缺这两个目录不是故障**，不要手动去建。

## 2. 界面地图

整个窗口分三块：**顶部工具栏**、**左侧栏**、**右侧详情**。

### 2.1 顶部工具栏

| 元素 | 功能 | 细节 |
| --- | --- | --- |
| 搜索框 | 按**姓名 / 别名**过滤，输入即筛（180ms 防抖） | 不搜正文；不区分大小写 |
| 全部阵营 | 按「所属阵营」过滤 | 选项由库里已有值自动生成 |
| 全部种族 | 按「种族」过滤 | 同上 |
| 全部标签 | 按「标签」过滤 | 同上；多标签角色命中任一即可 |
| 三个下拉可**叠加** | 关键词 + 阵营 + 种族 + 标签是「与」关系 | 某项被删空后自动回落到「全部」 |
| 写故事 | 打开独立故事编辑器 | 不绑定任何角色，见 §6.2 |
| 导出 | 全量导出为 JSON | 见 §9.1 |
| 导入 | 从 JSON 导入 | 追加，不覆盖，见 §9.2 |
| 新建角色 | 打开角色表单 | 姓名必填 |
| 齿轮 | 设置面板 | 见 §8 |

### 2.2 左侧栏

| 元素 | 说明 |
| --- | --- |
| **角色 / 故事** 两个标签 | 切换左侧列表的内容；选中块会从旧位置滑过去 |
| 计数徽标 | 当前列表条目数（受筛选影响） |
| 列表项 | 单击 → 右侧显示档案；键盘 **Enter / 空格** 同样可选中 |

左侧栏宽度会随布局变化：列表模式 300px，卡片/紧凑模式 352px。

### 2.3 右侧详情

- **上半**：主视觉区 —— 左边立绘（3:4 画框），右边姓名 / 别名 / 性格胶囊 / 五条基础信息 / 三个操作按钮。
- **下半**：四个标签页 —— 基础资料、能力武装、关系网络、小故事。
- 选中「故事」视角时，右侧换成**独立故事详情**（同样的位置，标题 + 标签 + 正文 + 参与角色）。

## 3. 角色档案

### 3.1 新建与编辑

点 **新建角色** 或详情里的 **编辑资料**，弹出同一个表单。表单按 7 个可折叠分区组织，点标题行展开 / 收起：

| 分区 | 字段 |
| --- | --- |
| 形象图片 | 头像（可裁剪）、立绘 |
| 基本信息 | 姓名\*、别名 / 称号、年龄、性别、种族、出生年月、出生地点、所属阵营、身份 / 职业、性格特征 |
| 能力列表 | 名称、描述、等级(Lv)，可增删任意多行 |
| 持有武器 | 名称、类型、描述，可增删任意多行 |
| 战斗属性 | 自由键值对「属性名 + 数值」，键名自定（如 hp / attack / 等级） |
| 关系网络 | 亲属 / 同伴 / 敌对 / 导师·学生 四组，每组「角色名 + 关系说明」 |
| 元信息 | 登场作品、首次出场、稀有度、标签 |

编写规则：

- **只有「姓名」必填**，其余留空即可，详情页空值统一显示 `—`（破折号）。
- **性格特征** 与 **标签** 用逗号分隔，中英文逗号（`,` `，`）都认。
  - 性格 → 详情页顶部显示成小胶囊；
  - 标签 → 进入顶部「全部标签」下拉，并显示在基础资料里。
- 关掉弹窗不保存，未保存的修改会直接丢失。表单没有自动草稿。

### 3.2 字段全表

数据库 `characters` 表共 20 列，其中 17 个是可在表单里编辑的业务字段：

| 字段 | 中文名 | 显示位置 |
| --- | --- | --- |
| `name` | 姓名 | 详情 h1、列表、搜索 |
| `alias` | 别名 / 称号 | 姓名下方、搜索 |
| `age` | 年龄 | 主视觉 dl、基础资料 |
| `gender` | 性别 | 主视觉 dl、基础资料 |
| `race` | 种族 | 主视觉上方小标签、种族筛选 |
| `birth_date` | 出生年月 | 基础资料 |
| `birth_place` | 出生地点 | 基础资料 |
| `affiliation` | 所属阵营 / 组织 | 主视觉上方小标签、阵营筛选 |
| `profession` | 身份 / 职业 | 主视觉 dl、基础资料 |
| `personality` | 性格特征 | 主视觉胶囊、基础资料 |
| `abilities` | 能力列表 | 能力武装页（JSON 数组） |
| `weapons` | 持有武器 | 能力武装页（JSON 数组） |
| `combat_stats` | 战斗属性 | 能力武装页（键值对） |
| `relationships` | 关系网络 | 关系网络页（四组） |
| `metadata` | 元信息 | 登场作品 / 首次出场 / 稀有度 / 标签 |
| `avatar_path` | 头像路径 | 列表、卡片 |
| `portrait_path` | 立绘路径 | 详情、卡片封面 |

另外三列（`id`、`created_at`、`updated_at`）由程序维护，只在基础资料里以「创建时间 / 更新时间」展示。

### 3.3 头像与立绘

| | 头像 | 立绘 |
| --- | --- | --- |
| 用在哪 | 列表左侧小图、卡片角标 | 详情主视觉、网格 / 紧凑卡片封面 |
| 选了图之后 | 进**裁剪窗**：拖动移位、滚轮缩放，圆形取景框内即最终效果 | 原图直接保存，不裁 |
| 存到哪 | `images/char_{角色ID}/avatar.png` | `images/char_{角色ID}/portrait.png` |
| 支持格式 | png / jpg / webp / gif | 同 |

三个要点：

1. **详情页取图顺序是「立绘 → 头像 → 姓名首字」**。只传了头像的角色，详情页会拿头像当立绘。
2. 立绘在画框里是**铺满**的（`cover`）：横图会裁掉两侧。想核对原图，去编辑弹窗里的立绘预览（那里是完整不裁的），或直接打开 `images/` 里的文件。
3. **替换**图片会删掉该槽位的旧文件；点「移除」并保存会同时删文件、清字段。删除角色会连整个 `images/char_{ID}/` 目录一起删。

### 3.4 删除角色

详情区右下角 **删除** → 弹二次确认 → 确认后：

- 角色记录删除；
- 该角色的**全部小故事级联删除**（`ON DELETE CASCADE`）；
- `images/char_{ID}/` 整个目录删除。

**没有回收站，删除即物理删除。** 重要角色建议先「导出角色卡」。

## 4. 能力 · 武器 · 战斗属性

都在「能力武装」标签页，三块结构一致：**列表 + 每行两列（名称 / 描述或数值）**。

| 区块 | 一行三个框 | 空的时候 |
| --- | --- | --- |
| 能力 | 名称 · 描述 · 等级(Lv) | 「暂无能力数据」 |
| 持有武器 | 名称 · 类型 · 描述 | 「暂无武器数据」 |
| 战斗属性 | 属性名 · 数值 | 「暂无战斗属性」 |

- 能力的「等级」会显示成 `Lv.数字` 徽章，武器的「类型」显示成类型徽章；留空就不显示徽章。
- 战斗属性是自由键值对 —— `hp / 1200`、`等级 / S`、`魔力 / 800` 都行，程序不做校验，按录入顺序显示。

战斗属性是自由的键值对 —— 想记 `hp / 1200`、`等级 / S`、`魔力 / 800` 都行，程序不做校验也不排序（按录入顺序显示）。

## 5. 关系网络

### 5.1 四组分类

| 组 | 用途 |
| --- | --- |
| 亲属 | 家人、血缘、收养 |
| 同伴 | 队友、盟友、朋友 |
| 敌对 | 宿敌、仇人、对手 |
| 导师 / 学生 | 师徒、带教关系 |

每组在编辑表单里是若干「角色名 + 关系说明」行，可增删。

### 5.2 关系图

「关系网络」标签页上半是 **SVG 径向图**：当前角色在中心，四组关系按类型着色（亲属绿 / 同伴蓝 / 敌对红 / 导师紫）围成一圈，每人一个圆点 + 名字。

- **悬停**圆点会放大；
- **点击**圆点或名字 → 跳到那个角色（前提是库里存在同名角色）。

### 5.3 关键限制

关系对象存的是**姓名字符串**，不是角色 ID。所以：

- 改名之后，别处指向旧名的关系**不会自动更新**，需要手动改；
- 画面上两个人名字相同就会指向同一个角色。

这是有意的设计（允许记录库中不存在的角色），代价就是改名要手动同步。

## 6. 故事

程序里有**两种故事**，共用一套正文编辑器和 Markdown 渲染：

| | 角色小故事 | 独立故事 |
| --- | --- | --- |
| 绑定 | 属于某一个角色 | 不属于任何角色 |
| 入口 | 角色详情 →「小故事」标签 → 撰写新故事 | 顶部「写故事」/ 左侧故事视角 |
| 排序 | 手动排序（上移 / 下移），构成成长时间线 | 按更新时间倒序，新写的在最上面 |
| 参与角色 | 就是所属角色本人 | 可多选，任意组合 |
| 显示位置 | 该角色档案内 | 左侧「故事」视角 |

### 6.1 角色小故事

- 列表里每张卡：标题 + 更新时间、标签胶囊、正文摘要（前 160 字，按 Markdown 渲染）；
- 四个按钮：**上移 / 下移 / 阅读 / 编辑**；
- 上移下移调整的是**成长时间线的顺序**（改的是 `sort_order`，不是按时间自动排），所以可以把"童年"排在"成年"前面；
- 阅读弹窗里可以直接 **编辑 / 删除**，底部还标着这条故事属于哪个角色。

### 6.2 独立故事库

左侧切到 **故事** 视角，或用顶部「写故事」。

- 编辑器是独立小窗口：标题（必填）、标签、参与角色、正文；
- **参与角色**：输入框搜名字，点下方候选项加入，胶囊上点 × 移除；
- 保存后出现在左侧故事列表，右侧展示全文 + 参与角色卡；
- 参与角色卡是 3:4 立绘 + 姓名，**点一下跳到该角色档案**。

### 6.3 双向可见

同一份数据两个方向都能看到：

- 角色 → 「小故事」标签下半的 **参与的故事（N）**：这个角色在别人的独立故事里出场过几次；
- 故事 → **参与角色（N）**：这篇故事有哪些角色。

### 6.4 Markdown 与安全

正文支持 Markdown：`**加粗**`、`# 标题`、`- 列表`、表格、代码块等。编辑器右上角 **预览** 可切实时渲染视图。

渲染结果会过一遍 HTML 清洗（DOMPurify），脚本与事件属性会被去掉 —— 也就是说**不能靠 Markdown 注入脚本**，复制来的可疑文本是安全的。

## 7. 搜索与筛选

| 控件 | 作用范围 | 说明 |
| --- | --- | --- |
| 搜索框 | 姓名、别名 | 子串匹配，忽略大小写 |
| 阵营 / 种族 / 标签 | 对应字段 | 精确相等；标签是「包含」 |
| 四者叠加 | 角色列表 | 全部满足才显示 |

- 筛选只影响**角色列表**，不影响故事列表；
- 下拉选项每次改动角色后自动重建，所以新填的阵营 / 种族 / 标签会立刻出现在下拉里；
- 筛到 0 条时列表区显示空状态提示，不会报错。

## 8. 列表布局与外观设置

点右上角 **齿轮** 打开设置面板，四组：

### 8.1 主题外观

| 选项 | 效果 |
| --- | --- |
| 浅色 | 白底蓝调，默认形态 |
| 深色 | 深灰底，主色反转为灰白（主按钮变"白底深字"） |
| 跟随系统 | 随 Windows 浅色 / 深色模式自动切换 |

切换**即时生效**并记住，下次启动沿用。

### 8.2 角色列表布局（三档）

| 布局 | 形态 | 适合 |
| --- | --- | --- |
| 列表 | 一行一个：40px 方形头像 + 姓名 + 别名 + 阵营 | 角色多、要快速扫 |
| 网格 | 2 列卡片墙，3:4 立绘当封面 | 想看立绘 |
| 紧凑 | 3 列密排，只留立绘和名字 | 角色非常多 |

选中后立即重排，偏好持久化。切换布局时侧栏会变宽，右侧详情不受影响。

### 8.3 动效

**减少动效** 开关：关掉转场、位移、缩放，只保留颜色反馈。
若 Windows 系统开启了「减少动态效果」，程序会自动跟随（两个开关是「或」关系，任意一个开就减动效）。

### 8.4 面板通透度

55%–100% 的滑杆，控制外壳的透明程度：数值越低，界面越透，背后的光晕越明显。
纯视觉偏好，不影响性能之外的任何功能。

底部 **恢复默认**：主题回「跟随系统」、布局回「列表」。

## 9. 导入 · 导出 · 备份

### 9.1 全量导出

顶部 **导出** → 确认 → 选保存位置，得到一个 JSON：

```json
{
  "app": "角色资料查询器",
  "version": 1,
  "exported_at": "2026-10-29T…",
  "characters": [ … 全部角色，含 base64 头像 / 立绘 … ],
  "stories": [ … 全部故事（两种都含）… ]
}
```

图片以 base64 内嵌，所以**一个文件就是完整备份**，换电脑只带这一个 JSON 也够。

### 9.2 导入

顶部 **导入** → 选 JSON → 确认。行为要点：

- **追加，不覆盖**：现有数据一条不删，导入的插在后面，ID 重新分配；
- **不去重**：同一个文件导两次就会有重复角色；
- 支持两种文件：全量导出的文件，以及单角色的「角色卡」文件；
- 图片会从 base64 还原到 `images/char_{新ID}/`。

### 9.3 单角色卡导出

详情区 **导出角色卡** → 文件名默认 `角色卡_{姓名}_{日期}.json`。内容是该角色 + 它的全部小故事 + 它参与过的独立故事。

用途：**喂给 AI 当人设上下文**，或单独分享一个角色。角色卡也能被上面的「导入」识别。

### 9.4 备份建议

程序没有自动备份。建议：

1. 每周「导出」一次，文件存到别的盘或网盘；
2. 或直接复制整个 `data/` + `images/` 目录（两者要成对，缺图片会显示首字占位）。

| 操作 | 效果 |

| 单击列表项 | 选中并在右侧展开 |

## 11. 数据存放位置

程序目录下两个文件夹，全部本地，**不联网、无账号、无云同步**：

```
data/characters.db        SQLite 数据库：角色、故事、关系（20 列 + 2 张故事表）
images/char_{ID}/         该角色的 avatar.* / portrait.*
```

- 数据库是标准 SQLite 文件，任何 SQLite 工具都能打开查看；
- 程序启动时若 `data/`、`images/` 不存在会自动创建；
- 这两个目录**不会**进入 Git 仓库（见 `09-构建与运维/01 §7`），只在你这台机器上。

## 12. 常见问题

**双击图标没反应 / 启动即退出？**
多半是原生模块 `better_sqlite3.node` 丢失（换 Node 版本、清理 node_modules 后常见）。
程序会弹框告知，按 `09-构建与运维/01 §5` 重新下载对应 Electron ABI 的预编译包即可。

**详情页立绘被裁掉两侧？**
画框是 3:4，横图按 `cover` 铺满必然裁边。想保留全景就换一张接近竖构图（或正方形）的图，或在编辑弹窗里查看完整预览。

**改角色名之后关系图错乱？**
关系存的是姓名字符串，改名要手动去相关角色的关系里同步。

**换电脑怎么搬？**
在新机器装好程序并启动一次（会建空库）→ 用「导入」选旧机器导出的 JSON。不要只拷 `data/` 而忘了 `images/`。

**误删了角色能恢复吗？**
不能。删除是物理删除，且级联删掉小故事和图片目录。靠备份或角色卡。

**导入两次会有重复吗？**
会。导入是纯追加，不判重。

**搜索为什么搜不到正文？**
搜索只匹配姓名和别名。正文检索目前没有实现（见「已知限制」）。

## 13. 功能一览（速查）

| 模块 | 能做 | 不能做 |
| --- | --- | --- |
| 角色 | 建档、编辑、删除、头像裁剪、立绘 | 批量编辑、字段自定义、回收站 |
| 能力 | 能力 / 武器 / 自由属性三块列表 | 数值计算、模板复用 |
| 关系 | 四组分类、径向关系图、点击跳转 | 双向自动对称、改名同步 |
| 故事 | 角色小故事（可排序）、独立故事（多参与角色）、Markdown 渲染 | 全文检索、版本历史 |
| 列表 | 搜索 + 三维筛选、三种布局 | 自定义排序、多选操作 |
| 外观 | 三主题、三布局、减少动效、通透度 | 自定义配色 |
| 数据 | 全量导出 / 导入、单角色卡、图片内嵌 | 自动备份、云同步、多端 |
