# 07-01 · 导入导出格式与流程

## 1. 适用范围

| 能力 | 主进程 | 数据层 | 渲染层 |
| --- | --- | --- | --- |
| 全量导出 | `data:export` | `exportAll({includeImages})` | `exportData()` |
| 全量导入 | `data:import` | `importAll(data)` | `importData()` |
| 单角色卡导出 | `characters:exportCard` | `exportCharacterCard(id)` | `exportCurrentCard()` |
| 角色卡导入 | 复用 `data:import` | `importAll()` 内部分支 | 同上 |

---

## 2. 全量导出

### 2.1 流程

```
顶部「导出」→ showConfirm（提示含图片 base64）→ bridge.exportData({includeImages:true})
  → dialog.showSaveDialog（默认 文档/角色资料导出_YYYY-MM-DD.json）
  → db.exportAll({includeImages:true})
  → fs.writeFileSync(JSON.stringify(data, null, 2))
  → 返回文件路径 → toast 显示路径
```

- 用户取消保存框 → `{ok:false, canceled:true}`，渲染层静默跳过（不弹错误）；
- 列表为空时提前拦截：`toast('当前没有可导出的角色','warn')`；
- **当前固定 `includeImages: true`**（UI 上没有开关），所以导出的 JSON 通常有几十 MB。

### 2.2 文件结构

```json
{
  "app": "角色资料查询器",
  "version": 1,
  "exported_at": "2026-10-29T12:00:00.000Z",
  "characters": [
    {
      "id": 3,
      "name": "玛莉",
      "abilities": [{ "name": "火球术", "description": "…", "level": 2 }],
      "relationships": { "family": [], "companions": [], "rivals": [], "mentors": [] },
      "avatar_path": "images/char_3/avatar.png",
      "portrait_path": "images/char_3/portrait.png",
      "avatar_data": "data:image/png;base64,…",
      "portrait_data": "data:image/png;base64,…",
      "created_at": "…", "updated_at": "…"
    }
  ],
  "stories": [
    {
      "id": 12,
      "character_id": 3,
      "title": "初遇",
      "content": "## 一\n…",
      "tags": "序章,相遇",
      "sort_order": 0,
      "created_at": "…", "updated_at": "…",
      "participant_ids": [3, 5]
    }
  ]
}
```

要点：

- `characters` 里的 JSON 字段是**已解析的对象**（不是字符串），可读性好；
- `avatar_data` / `portrait_data` 为 base64 data URL，`includeImages: false` 时不出现；
- `stories` 按 `COALESCE(character_id,0), sort_order, id` 排序，导出顺序即恢复顺序；
- `participant_ids` 是**旧库的角色 id**，导入时靠 `idMap` 映射成新 id。

## 3. 单角色卡导出

### 3.1 文件结构

```json
{
  "app": "角色资料查询器",
  "export_type": "character_card",
  "version": 1,
  "exported_at": "…",
  "character": {
    "id": 3, "name": "玛莉", "…": "全部角色字段",
    "stories": [{ "title": "初遇", "content": "…", "tags": "…", "sort_order": 0 }],
    "participated_stories": [{ "title": "群像夜谈", "content": "…", "tags": "…" }]
  }
}
```

- **不带图片**：角色卡定位是「文本上下文打包」，用于分享设定或投喂 AI，图片会让文件膨胀且无意义；
- `stories` 只含该角色的小故事；`participated_stories` 是它参与的独立故事（无 `sort_order`）；
- 默认文件名 `角色卡_{姓名}_{YYYY-MM-DD}.json`，姓名里的 `\ / : * ? " < > |` 替换为 `_`。

### 3.2 与全量导出的区别

| 维度 | 全量导出 | 角色卡 |
| --- | --- | --- |
| 范围 | 所有角色 + 所有故事 | 1 个角色 + 其故事 |
| 图片 | 可内嵌 base64 | 不含 |
| 结构 | 平铺 `characters[]` / `stories[]` | 嵌套在 `character` 下 |
| 标识 | 无 `export_type` | `export_type: 'character_card'` |
| 主要用途 | 备份 / 迁移 | 分享 / 喂 AI |

## 4. 导入

### 4.1 流程

```
顶部「导入」→ showConfirm（说明是追加、不覆盖）→ bridge.importData()
  → dialog.showOpenDialog（*.json）
  → fs.readFileSync
  → JSON.parse（失败：'JSON 解析失败，文件格式不正确'）
  → 校验 data.characters 是数组（否则：'不是有效的角色数据文件（缺少 characters 数组）'）
  → db.importAll(data)   ← 事务
  → 返回 { charCount, storyCount } → toast 统计
  → loadCharacters() 刷新
```

### 4.2 角色卡格式的兼容

`importAll()` 开头做格式归一：

```js
if (data.export_type === 'character_card' && data.character && !Array.isArray(data.characters)) {
  const c = data.character;
  // 内嵌小故事：补上 character_id（旧 id）与 sort_order（缺省用下标）
  const nested = (c.stories || []).map((s, i) => ({ ...s, character_id: c.id, sort_order: s.sort_order ?? i }));
  // 参与的故事：还原成独立故事（character_id = null），并把导入角色设为参与者
  const part = (c.participated_stories || []).map(s => ({ ...s, character_id: null, participant_ids: [c.id] }));
  data = { characters: [charOnly], stories: nested.concat(part) };
}
```

归一后与全量格式走**完全相同的导入路径**，不需要两套逻辑。

### 4.3 事务与 ID 映射

```js
const result = db.transaction(() => {
  const idMap = new Map();              // 旧角色 id → 新角色 id

  for (const c of data.characters) {
    // 去掉 id / 时间戳 / 图片 data
    // 只插入 CHAR_FIELDS 里的键
    // 有 avatar_data / portrait_data 则写入 images/char_{newId}/
    idMap.set(c.id, newId);
  }

  for (const s of data.stories) {
    const cid = s.character_id != null ? idMap.get(s.character_id) : null;
    if (s.character_id != null && !cid) continue;   // 关联角色不存在 → 跳过该故事
    // INSERT stories
    // participant_ids 映射后 setStoryParticipants
  }

  return { charCount, storyCount };
})();
```

关键设计：

1. **必须是事务**：几百个角色 + 上千条故事，中途失败若已写入部分数据，会造成难以收拾的半成品库；
2. **ID 必须重映射**：导入是追加，新库的自增 id 与旧库不同；
   故事表的 `character_id` 与参与表的 `character_id` 都要换成新 id，否则故事会挂到别的角色上；
3. **跳过孤儿故事**：`character_id` 指向的角色不在本次导入范围内时，跳过并计入「少导」，
   而不是插入一条挂空的故事；
4. **图片目录名用新 id**：`images/char_{newId}/`，`writeImageDataUrl()` 返回相对路径。

### 4.4 追加语义

- **不去重**：同一份文件导两次 → 两套角色，名字一样但 id 不同；
- **不覆盖**：现有数据完全不动（除自增 id 递增）；
- 返回值统计的是「本次插入的数量」，不是库内总数。

## 5. 边界与已知限制

| 情况 | 现状 |
| --- | --- |
| 导出文件体积 | 图片多时可达数十 MB，`JSON.stringify(..., 2)` 还带缩进，读写有明显停顿 |
| 导入大文件 | 同步 `readFileSync` + 事务内逐条插入，主进程会短暂卡住（窗口无响应） |
| 重复导入 | 会产生重复角色，需手工删除 |
| 图片丢失 | `readImageDataUrl()` 找不到文件时返回 `null`，导出后该角色在别处导入就没有图 |
| 跨版本兼容 | 仅认 `version: 1`；未来加字段需在 `importAll` 里补默认值 |
| 无导入预览 | 不能先看「会导入哪些内容」再确认 |

---

## 6. 修改指引

| 需求 | 位置 |
| --- | --- |
| 给全量导出加「不含图片」选项 | `renderer.js` 的 `exportData()` 传 `{includeImages:false}`，可在确认框里加一个复选项 |
| 导入去重（按姓名） | `importAll()` 里先查同名角色，命中则 `UPDATE` 而非 `INSERT`，注意 idMap 仍要指向已有 id |
| 支持增量合并故事 | 需要给故事加稳定业务键（如 `uuid`），否则无法判断「同一篇」 |
| 导出为可读 Markdown / 文本 | 新增 `exportCharacterCardText()`，把角色字段拼成 Markdown，纯文本更适合投喂 AI |
| 导入前预览 | 拆成两步 IPC：`data:preview`（解析并返回摘要）+ `data:importFile`（按用户确认执行） |

## 8. 验证方式

```bash
# 1. 导出后结构检查（用 Electron 运行时，避免 ABI 问题）
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe -e "
const db=require('./database'); db.initDatabase();
const d=db.exportAll({includeImages:false});
console.log('keys', Object.keys(d));
console.log('chars', d.characters.length, 'stories', d.stories.length);
console.log('sample', JSON.stringify(d.characters[0]).slice(0,120));
console.log('participant_ids', d.stories[0] && d.stories[0].participant_ids);
"

# 2. 导入幂等性观察（同一文件导两次）
# 导出前记录角色数 N → 导入同一文件 → 角色数应为 N + N
```

角色卡格式：

```bash
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe -e "
const db=require('./database'); db.initDatabase();
const c=db.exportCharacterCard(db.listCharacters()[0].id);
console.log('type', c.export_type, 'stories', c.character.stories.length,
            'participated', c.character.participated_stories.length);
const r=db.importAll(JSON.parse(JSON.stringify(c)));
console.log('imported', r);
"
```

预期：`importAll` 把角色卡拆成 1 个角色 + N 篇故事，返回 `{charCount:1, storyCount:N+参与数}`。
