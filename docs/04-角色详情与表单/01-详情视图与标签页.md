# 04-01 · 详情视图与标签页

## 1. 适用范围

| 层 | 位置 |
| --- | --- |
| 结构 | `index.html` → `#detailContent`（角色详情）、`#globalStoryDetail`（独立故事详情）、`#detailEmpty` / `#gsEmptyDetail` |
| 逻辑 | `renderer.js` → `renderDetail()` / `renderBasicTab()` / `renderAbilitiesTab()` / `renderRelationsTab()` / `renderStoriesTab()` / `renderParticipatedSection()` / `renderGlobalStoryDetail()` / `renderParticipantCards()` / `bindTabSwitching()` |
| 样式 | `styles.css` → `.hero` / `.portrait-frame` / `.quick-info` / `.tab-panel` / `.panel-card` / `.info-row` / `.kv-row` |

## 2. 两个详情视图互斥

右侧 `.detail` 区域有三块，通过 `hidden` class 切换，同一时刻只显示一块：

| 状态 | 显示 | 触发 |
| --- | --- | --- |
| 无选中 | `#detailEmpty`（「← 从左侧列表选择一个角色查看档案」） | `showEmptyDetail()` |
| 角色详情 | `#detailContent` | `selectCharacter(id)` → `renderDetail(id)` |
| 独立故事详情 | `#globalStoryDetail` | `selectGlobalStory(id)` → `renderGlobalStoryDetail()` |

`renderGlobalStoryDetail()` 第一行就 `$('#detail').classList.add('hidden')`——
把整个角色详情区隐藏，换成故事详情区，返回时由 `switchSideView('chars')` 复位。

## 3. 主视觉区（Hero）

```
┌──────────────┬──────────────────────────────────────┐
│              │ 姓名（h1） / 别名                     │
│   立绘        │ 性格 chip 行                          │
│  (3:4 画框)   │ 性别 · 种族 · 所属 · 身份 · 登场作品   │
│              │ [✏️ 编辑资料] [📤 导出角色卡] [🗑 删除] │
└──────────────┴──────────────────────────────────────┘
```

- **立绘**：有 `portrait_path` 且 `image:getUrl` 返回非空 → 显示 `<img id="portraitImg">`；
  否则显示 `#portraitFallback`：首字大字 + 姓名 + 「暂无立绘」。
- **立绘必须铺满框（v2.0.2）**：`.portrait-img` 是 `width/height:100%` + `object-fit: cover`，
  不是 `max-width/max-height` + `contain`。原因：本工程的立绘**多为横图**
  （实测 1632×1024，比例 1.59），`contain` 塞进 300×380 的画框后只占 300×188，
  上下各留一条 96px 的渐变空白 —— 这就是「登录后首屏看着像没图」的观感。
  `cover` 铺满后横向会裁掉约一半（1.59 的图在 0.789 的框里保留中间 49.5%），
  这是刻意的取舍：详情区的立绘任务是「快速认出这个人」，不是「看全整张场景图」；
  要看全景走「编辑资料 → 立绘预览」（`.image-preview img` 仍是 `contain`）。
- **`object-position: 50% 25%`**：横图只有横向溢出、纵向参数不生效（居中即可）；
  竖图（比 0.789 更瘦）才会纵向溢出，此时 25% 让取景偏上、优先保住头部，
  而不是用 50% 拦腰截断。
- **快速印象**：`#qiName` / `#qiAlias` / `#qiPersonality`（chip）/
  `#qiGender` / `#qiRace` / `#qiAffiliation` / `#qiProfession` / `#qiWork`。
  空值统一显示 `—`（破折号），不是空白。
- **性格 parsing**：`split(/[,，]/)`，中英文逗号都支持，过滤空项。
- **三个操作按钮**：编辑（打开表单）、导出角色卡、删除（自定义确认框）。

## 4. 四个标签页

结构：`.tab-btn[data-tab="basic|abilities|relations|stories"]` + `.tab-panel#tab-{name}`。

```js
function bindTabSwitching() {
  $$('.tab-btn').forEach(btn => btn.addEventListener('click', () => {
    $$('.tab-btn').forEach(b => b.classList.toggle('active', b === btn));
    $$('.tab-panel').forEach(p => p.classList.toggle('active', p.id === 'tab-' + btn.dataset.tab));
  }));
}
```

- 切换是**纯 class 切换**，不重新渲染数据，四个 panel 的内容在 `renderDetail()` 时一次全部生成。
- **切换角色不会重置标签页**：用户停在「关系网络」时点另一个角色，仍停在「关系网络」。
  这是刻意设计——对比多个角色的关系时不必每次重新点。

### 4.1 基础资料 `#tab-basic`

`renderBasicTab(c)` 生成 16 行 `dt/dd`，顺序固定：
姓名、别名/称号、年龄、性别、种族、出生年月、出生地点、所属阵营/组织、身份/职业、性格特征、
登场作品、首次出场、稀有度、标签、创建时间、更新时间。

- 性格在这里用「、」连接成一行，与 Hero 区的 chip 展示形成互补；
- 标签走 `getTags(c).join('、')`，兼容数组/字符串两种存储。

### 4.2 能力武装 `#tab-abilities`

三块独立渲染，各有空状态文案：

| 区块 | 容器 | 数据 | 展示 |
| --- | --- | --- | --- |
| 能力 | `#abilitiesList` | `abilities[]` | `.card`：名称 + `Lv.N` 徽标 + 描述 |
| 武器 | `#weaponsList` | `weapons[]` | `.card`：名称 + 类型徽标 + 描述 |
| 战斗属性 | `#combatStatsList` | `combat_stats{}` | `.kv-row` 键值对 |

- `Array.isArray()` 防御：老数据或手工改坏的 JSON 不会导致渲染崩溃；
- 名称缺失时用「能力 1」「武器 1」兜底；
- `level` / `type` 为空则不渲染徽标，避免空胶囊。

### 4.3 关系网络 `#tab-relations`

分上下两块：`#relationGraph`（SVG 图）+ `#relationGroups`（四类清单）。
实现细节见 [05-关系网络](../05-关系网络/01-SVG关系图与跳转.md)。

### 4.4 小故事 `#tab-stories`

`renderStoriesTab(c)` 是**异步**的（`bridge.listStories`），返回后渲染：

- `#storyCount` 显示数量；
- 每张 `.story-card`：标题 + 更新时间 + 标签 chip + **前 160 字 Markdown 预览** + 四个按钮；
- 按钮：`⬆` / `⬇`（时间线重排，首尾按钮无效时直接 return）、`📖 阅读`、`✏️ 编辑`；
- 点击卡片任意位置（非按钮）默认打开阅读弹窗；
- 空状态：「还没有小故事，点击「撰写新故事」开始记录。」
- 失败状态：`catch` 里显示「加载小故事失败」，不弹 toast（避免一次渲染弹多个错）。

`truncateText(text, 160)` 截断后再交给 `window.MD.render()`——
先截断再渲染，避免在半句 Markdown 语法中间切断产生破标签。

### 4.5 参与的故事

`renderParticipatedSection(c)` 独立于小故事 Tab 之外，反向列出该角色参与的**独立故事**，
点击进入故事详情。数据来自 `stories:listParticipated`。

## 5. 独立故事详情

`renderGlobalStoryDetail(story)` 渲染内容：

| 区块 | 元素 | 内容 |
| --- | --- | --- |
| 标题 | `#gsTitle` | 故事标题 |
| 元信息 | `#gsMeta` | 标签 chip + 「创建：… · 更新：…」 |
| 正文 | `#gsContent` | `window.MD.render(content)`，空内容显示「（空）」 |
| 参与角色 | `#gsParticipants` | `renderParticipantCards()` |
| 操作 | `#btnGSBack` / `#btnGSEdit` / `#btnGSDelete` | 返回角色视图 / 编辑 / 删除 |

`renderParticipantCards(sel, participants)` 是**共用函数**（故事详情 + 阅读弹窗）：

- 按姓名 `localeCompare(…, 'zh')` 排序，标题显示「参与角色（N）」；
- 每张卡：3:4 立绘（无图显示首字）+ 姓名；立绘同样是 `object-fit: cover`（v2.0.2 起，与详情区一致）
- 立绘异步加载，`img.onload` 后才隐藏占位；
- 点击卡片 → `jumpToCharacterById(id)`：切回角色视图 → `selectCharacter` → toast 提示。

## 6. 修改指引

| 需求 | 位置 |
| --- | --- |
| 加一个标签页 | ① `index.html` 加 `.tab-btn[data-tab="xxx"]` 与 `#tab-xxx.tab-panel`；② `renderDetail()` 调新的 `renderXxxTab(c)`；③ 无需动 `bindTabSwitching()`（自动适配） |
| 改基础资料字段顺序/文案 | `renderBasicTab()` 的 `rows` 数组，顺序即展示顺序 |
| 让切换角色时回到第一个 Tab | `renderDetail()` 末尾手动重置 `.tab-btn` / `.tab-panel` 的 `active` |
| 加详情区操作按钮 | HTML 加按钮 → `bindEvents()` 绑定 → 回调里用 `state.currentId` 取当前角色 |
| 改立绘裁切方式 | `styles.css` 的 `.portrait-img`：`object-fit`（`cover` 铺满 / `contain` 看全景）+ `object-position`（`50% 25%` 偏上取景）。参与角色小卡是 `.participant-portrait-img`，策略必须同步，否则两处观感不一致 |
| 改小故事预览字数 | `renderStoriesTab()` 里 `truncateText(s.content, 160)` |
| 改空状态文案 | 对应 `empty-inline` / `empty-state` 的字符串 |
