# 09-02 · 故障排查手册

> 按「现象 → 根因 → 处理」组织。优先看第 1 节（启动类故障占绝大多数）。

---

## 1. 启动类

### 1.1 双击桌面快捷方式完全没反应

**现象**：图标能点，鼠标转一下圈就没了，任务栏无窗口，进程列表里却可能有 `electron.exe`。

**根因链**（v1.1 实际排查结论）：

```
better_sqlite3.node 丢失 / ABI 不匹配
  → db.initDatabase() 抛错
  → 异常发生在 createWindow() 之前（app.whenReady 内）
  → 进程不会退出（没有窗口被「关闭」过），变成无窗口僵尸
  → 该僵尸持有 requestSingleInstanceLock()
  → 之后每次双击都被判定为「第二实例」→ app.quit() → 静默退出
```

**处理步骤**：

1. 任务管理器结束所有 `electron.exe`（释放单实例锁）；
2. 检查二进制是否存在：
   ```bash
   ls -l node_modules/better-sqlite3/build/Release/better_sqlite3.node
   ```
3. 缺失则按 [09-01 第 5 节](01-启动脚本与自检.md) 从 npmmirror 恢复；
4. 用 Electron 运行时验证：
   ```bash
   ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe -e \
     "const D=require('better-sqlite3');new D('data/characters.db',{readonly:true});console.log('OK')"
   ```
5. 重新双击。仍无声？按 1.2 检查环境变量。

**已加固**：`main.js` 的 `initDatabase()` 现在包在 try/catch 里，失败会弹「启动失败」错误框并 `app.quit()`，
正常情况下不再产生僵尸进程。

---

### 1.2 报 `Cannot read properties of undefined (reading 'requestSingleInstanceLock')`

**根因**：环境里有 `ELECTRON_RUN_AS_NODE=1`。这个变量会让 `electron.exe` 以**纯 Node 模式**运行，
`require('electron')` 返回的是路径字符串而不是模块对象，`app` 为 `undefined`。

**判断**：

```bash
echo "[$ELECTRON_RUN_AS_NODE]"
```

**处理**：

- 从资源管理器双击快捷方式**不受影响**（Explorer 的环境干净）；
- 终端里启动需清掉：
  ```bash
  env -u ELECTRON_RUN_AS_NODE "./node_modules/electron/dist/electron.exe" "D:/oc资料"
  ```
- PowerShell：
  ```powershell
  Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
  ```
- 若用户级/系统级环境变量真的存在（用 `[Environment]::GetEnvironmentVariable('ELECTRON_RUN_AS_NODE','User')` 确认），
  需要手动删除，否则所有终端启动都会失败。

> 这个坑极易误判成「代码坏了」——报错里 `requestSingleInstanceLock` 是 `app` 的方法，
> 而 `app` 只在真正的 Electron 主进程里存在。

---

### 1.3 启动弹「启动失败 / 数据库初始化失败」

这是 v1.1 加的兜底弹窗，文案里已给出原因与处理。常见三种：

| 弹窗里的错误 | 处理 |
| --- | --- |
| `Could not locate the bindings file` | `.node` 丢失 → 09-01 第 5 节恢复 |
| `NODE_MODULE_VERSION 130 was compiled against…` | ABI 不匹配 → `npm run rebuild` 或下载对应版本预编译包 |
| `SQLITE_CANTOPEN` / `unable to open database file` | `data/` 目录无写权限，或被安全软件锁定 → 检查目录属性 / 加白名单 |

---

### 1.4 第二次启动不弹新窗口（这是设计）

单实例锁生效：第二次启动只把已有窗口恢复并聚焦。**不是 bug**。
若第一次启动的窗口被最小化到托盘区/其他桌面，可能只是找不到窗口，用 Alt+Tab 确认。

## 2. 数据与显示类

### 2.1 左侧列表为空

| 可能 | 确认方式 | 处理 |
| --- | --- | --- |
| 库里确实没有角色 | 详情区显示「← 从左侧列表选择一个角色」 | 点「＋ 新建角色」 |
| 筛选条件过严 | 检查搜索框与三个下拉 | 全部清空 / 恢复「全部 X」 |
| 数据库被换成了空文件 | `select count(*) from characters` | 用「导入」恢复备份 |
| 布局切换后高度塌陷 | 开发者工具看 `#charList` 高度是否 0 | 检查 `#charsView` 的 `flex:1; min-height:0` 是否被覆盖 |

### 2.2 头像 / 立绘不显示

1. 查库里的路径：
   ```bash
   ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe -e "
   const D=require('better-sqlite3');const d=new D('data/characters.db',{readonly:true});
   d.prepare('select id,name,avatar_path,portrait_path from characters').all().forEach(r=>console.log(r));"
   ```
2. 路径为空 → 重新在编辑弹窗选图保存；
3. 路径非空但文件不在 → `images/char_{id}/` 被清理过，重新选图；
4. 文件在但界面不显示 → 检查扩展名是否在白名单（`png/jpg/jpeg/webp/gif`），
   以及 `image:getUrl` 是否返回 `null`（可在 Console 里 `await window.api.getImageUrl('images/char_3/avatar.png')`）。

### 2.3 换了头像但界面还是旧图

正常情况不会发生：`image:getUrl` 会给 URL 加 `?t=mtimeMs`。
若仍出现，说明文件 `mtime` 没变（某些同步盘/复制工具会保留原时间戳），
可在裁剪后重新保存一次，或临时清空 `images/char_{id}/` 重选。

### 2.4 浅色主题启动时闪一下深色

**根因**：`main.js` 的 `backgroundColor: '#171a21'` 写死深色，主进程读不到 localStorage。
**这是已知限制**，修复方案见 [08-01 第 7 节](../08-主题与设置/01-主题系统与防闪色.md)。

### 2.5 关系图点击节点没反应

- 跳转依赖**姓名/别名精确匹配**（忽略大小写与首尾空格）；
- 关系里写「凯」而角色叫「凯尔」→ 必须一致，否则只会弹 warn「未找到名为…的角色」；
- 同名角色存在两个 → 会跳到列表里第一个匹配项（`state.characters` 顺序 = 更新时间倒序）。

## 3. 故事与编辑器类

### 3.1 编辑器显示「未获取到编辑数据」

- 编辑器窗口必须由主窗口的「写故事 / 撰写新故事 / 编辑」入口打开，
  它依赖主进程挂在窗口对象上的 `_editorPayload`；
- 直接双击 `story-editor.html` 或用浏览器打开，一定拿不到数据；
- 若从正确入口打开仍报错，检查 `main.js` 的 `createStoryEditorWindow` 是否把 payload 挂上。

### 3.2 保存故事后主窗口没刷新

`stories:saved` 事件链路：

```
IPC handler → notifyStoriesSaved() → mainWindow.webContents.send
           → preload onStoriesSaved → renderer 刷新
```

排查点：`mainWindow` 是否已销毁（关窗后 handler 仍可能被调用）、
`character_id` 是否为 `null`（独立故事走另一条刷新分支）。

### 3.3 ⬆⬇ 排序无效

- 首条不能再上移、末条不能再下移（代码里直接 return，无提示）；
- 排序只对**角色小故事**生效，独立故事固定 `sort_order = 0`；
- 若重启后顺序还原，检查 `setStoryOrder` 是否被 `character_id` 条件挡住（说明前端传了错误的角色 id）。

### 3.4 故事正文格式错乱

- Markdown 渲染依赖 `node_modules/marked` 与 `dompurify`，缺失时降级为纯文本（换行保留、语法不解析）；
- 检查 `node_modules/marked/marked.min.js` 是否存在；
- 表格/任务列表需要 GFM（已开启）。
- 卡片预览是**先截断 160 字再渲染**，长代码块可能被截半个——正常现象，点开阅读全文即可。

## 4. 导入导出类

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 导入报「JSON 解析失败」 | 文件被编辑器改坏 / 不是 UTF-8 / 有 BOM | 用 VS Code 另存为 UTF-8 无 BOM |
| 导入报「缺少 characters 数组」 | 传了角色卡以外的格式，或文件是数组而非对象 | 确认导出时选的是「导出」或「导出角色卡」 |
| 导入后角色重复 | 追加语义，不去重 | 先备份，再手工删除重复项（或用全量导出重建库） |
| 导入后图片没了 | 导出时用的 `includeImages:false`，或原图已被删 | 重新导出（当前 UI 固定带图） |
| 导出文件几十 MB | 图片以 base64 内嵌，体积约为原图 ×1.37 | 正常；需要小文件就导出「角色卡」（不含图） |
| 导入大文件时窗口卡住 | 同步 `readFileSync` + 事务内逐条插入 | 等待即可；不要在此期间关窗口 |

## 5. 环境与工具类

### 5.1 `tar` 解包报 `Cannot open: No such file or directory`（路径含中文）

Git Bash 的 `tar` 会把 `D:\...` 当成「远程主机:路径」。处理：

```bash
tar --force-local -xzf bs3.tar.gz -C node_modules/better-sqlite3
# 或先 cd 到目标目录再用相对路径
```

### 5.2 `npm run rebuild` 失败

报错里出现 `MSBuild` / `Visual Studio` / `gyp ERR` → 本机没装 C++ 工具链。
不要在这上面耗时，直接下载预编译包（09-01 第 5 节）。

### 5.3 截图 / 视觉验证不可用

本机环境限制：`webContents.capturePage()` 可能返回 0 字节，PowerShell 的 `System.Drawing`
也可能被安全策略拦截。替代方案（临时钩子，用完删除）：

```js
// main.js 里临时加
mainWindow.webContents.once('did-finish-load', async () => {
  const r = await mainWindow.webContents.executeJavaScript(
    "(() => { const c=document.querySelector('.char-card'); const s=getComputedStyle(c);" +
    " return { w: c.offsetWidth, h: c.offsetHeight, transform: s.transform }; })()");
  require('fs').writeFileSync('D:/probe.json', JSON.stringify(r, null, 2));
  app.quit();
});
```

悬停态验证用 `webContents.sendInputEvent({ type:'mouseMove', x, y })` 打真实鼠标事件，
再读 `getComputedStyle` 与 `matches(':hover')`。

**注意**：这类钩子绝不能留在正式代码里（v1.2 / v1.3 的钩子均已确认移除）。

## 6. 一键自检清单

出问题时按顺序跑，能覆盖 90% 的情况：

```bash
cd "D:/oc资料"

# 1. 语法
npm run check && echo "① 语法 OK"

# 2. 原生模块存在
ls -l node_modules/better-sqlite3/build/Release/better_sqlite3.node
echo "② 二进制 ↑"

# 3. 数据库可读
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe -e "
const D=require('better-sqlite3');const d=new D('data/characters.db',{readonly:true});
console.log('③ chars', d.prepare('select count(*) c from characters').get().c,
            'stories', d.prepare('select count(*) c from stories').get().c);"

# 4. 无僵尸进程
powershell -c "Get-Process electron -ErrorAction SilentlyContinue | Select-Object Id,MainWindowTitle"

# 5. 环境变量干净
echo "⑤ ELECTRON_RUN_AS_NODE=[${ELECTRON_RUN_AS_NODE}]"
```

全部通过仍然打不开 → 看 `npm start` 的终端输出，异常栈通常直接指向问题文件。

## 8. 验证方式

本手册本身是排错结果的沉淀，验证方式是「按文档复现」：

- 故意把 `better_sqlite3.node` 改名 → 启动应弹错误框（而不是静默无反应）；
- 故意设 `ELECTRON_RUN_AS_NODE=1` 后启动 → 应复现 1.2 的报错，按文档处理后恢复；
- 故意删掉 `node_modules/marked` → 故事预览应降级为纯文本而不是白屏。
